## 1. Rendering `CoChem-GEOM` Structural Comparisons (`render_geom_comparison`)

In the CoChem rotational-spectroscopy pipeline, fitted spectroscopic constants from `CoChem-SPYFY` (JSON or Pickett `.var`/`.lin`/`.fit`) are ingested by `CoChem-GEOM` to produce a verified `cochem.geom.structural-comparison/1` JSON artifact comparing converged *ab initio* $r_e$ (ORCA CCSD/cc-pVTZ and PySCF CCSD/cc-pVDZ), Kraitchman $r_s$, weighted $r_0$, and semi-experimental $r_e^{\mathrm{SE}}$.

`render_geom_comparison` renders separated publication-grade PNG + PDF figures with SHA-256 provenance footers and manifests, preserving any uncomputed $r_e^{\mathrm{SE}}$ column as an explicit `PENDING` slot (never equated to $r_0$ or $r_e$).

### CLI Example

```bash
cochem-scribe render-geom \
  --input path/to/h2o_t_geom_01_comparison.json \
  --out-png benchmarks/verified_figures/h2o_geom_comparison.png \
  --out-pdf benchmarks/verified_figures/h2o_geom_comparison.pdf \
  --manifest benchmarks/verified_figures/manifest_sha256.json
```

### Python Example

```python
from cochem_scribe.renderers import render_geom_comparison

receipt = render_geom_comparison(
    comparison_json_path="path/to/h2o_t_geom_01_comparison.json",
    out_png="out/h2o_geom_comparison.png",
    out_pdf="out/h2o_geom_comparison.pdf",
    manifest_path="out/manifest_sha256.json",
)
print("PNG SHA-256:", receipt["outputs"]["png_sha256"])
print("PDF SHA-256:", receipt["outputs"]["pdf_sha256"])
print("PENDING columns:", receipt["pending_columns"])
```

## 2. Rendering `CoChem-KINETIC` Reaction Profiles (`render_kinetic_rxn_profile`)

`render_kinetic_rxn_profile` ingests a verified 5-stationary-point `stationary_table.csv` (`R`, `TS1`, `Int_tet`, `TS2`, `P`) generated by `CoChem-KINETIC` (e.g., `CHEM 312` Team 1 formate and Team 4 carbonate pathways).

- **Strict mode (default, `strict=True`):** Validates that all five canonical stationary points are converged, finite, and match expected imaginary-frequency counts (`n_imag = 0` for `R`, `Int_tet`, `P`; `n_imag = 1` for `TS1`, `TS2`). Any missing, `PENDING`, unconverged, or Hessian-mismatched state raises `ValueError`.
- **Allow-pending mode (`--allow-pending` / `strict=False`):** Renders verified points numerically and marks unverified states explicitly as `PENDING` with zero fabricated bars.

### CLI Example

```bash
# Strict publication render (fails if any stationary point is unverified)
cochem-scribe render-kinetic \
  --input path/to/stationary_table.csv \
  --out-png benchmarks/verified_figures/chem312_team1_formate_rxn_profile.png \
  --out-pdf benchmarks/verified_figures/chem312_team1_formate_rxn_profile.pdf \
  --energy-column delta_g_qrrho_kcal \
  --title "CHEM 312 Team 1: Formate Esterification Free-Energy Profile" \
  --manifest benchmarks/verified_figures/manifest_sha256.json

# Exploratory render allowing explicit PENDING slots
cochem-scribe render-kinetic \
  --input path/to/partial_stationary_table.csv \
  --out-png out/partial_rxn_profile.png \
  --out-pdf out/partial_rxn_profile.pdf \
  --allow-pending
```

### Python Example

```python
from cochem_scribe.renderers import render_kinetic_rxn_profile

receipt = render_kinetic_rxn_profile(
    stationary_csv_path="path/to/stationary_table.csv",
    out_png="out/rxn_profile.png",
    out_pdf="out/rxn_profile.pdf",
    energy_column="delta_g_qrrho_kcal",
    strict=True,
    title="Reaction-Coordinate Free-Energy Profile (298.15 K)",
    manifest_path="out/manifest_sha256.json",
)
print("Verified states:", receipt["verified_states"])
print("Input SHA-256:", receipt["input_sha256"])
```

## 3. Verifying the 19-Entry Drive Source Register (`verify_source_register`)

`manifests/in_scope_figure_register.json` tracks cryptographic metadata and Instructor Google Drive collection pointers for all 19 in-scope figures without duplicating private manuscript scripts or archival PDFs into this public repository:

- **FTMW methodology manuscript:** 4 figures
- **Keratin v1.1.0:** 15 figures

`verify_source_register` checks 64-hex SHA-256 integrity, uniqueness, Drive URL format, exact collection counts (`4 + 15 = 19`), and executes the out-of-scope encyclopedia exclusion gate across every field.

### CLI Example

```bash
# Verify the packaged 19-entry JSON register manifest
cochem-scribe verify-register

# Verify a custom CSV register and re-hash all 19 Drive scripts & archived PDFs on disk
cochem-scribe verify-register \
  --register path/to/in_scope_figure_register.csv \
  --verify-on-disk
```

### Python Example

```python
from cochem_scribe.register import verify_source_register

report = verify_source_register(verify_on_disk=False)
assert report["passed"] is True
assert report["total_figures"] == 19
print("Collections:", report["collection_counts"])
print("Register SHA-256:", report["register_sha256"])
```

## 4. Running the Out-of-Scope Encyclopedia Exclusion Gate (`audit_farir_exclusion`)

`audit_farir_exclusion` scans text, structured dictionaries/lists, single files, or entire directories to enforce the hard scope boundary keeping out-of-scope encyclopedia material out of `CoChem-SCRIBE` releases and manifests.

### CLI Example

```bash
# Audit a directory or manifest (exits 0 on pass, 1 on violation)
cochem-scribe audit-farir --path manifests/in_scope_figure_register.json
cochem-scribe audit-farir --path benchmarks/verified_figures
```

### Python Example

```python
from pathlib import Path
from cochem_scribe.register import FarIRExclusionError, audit_farir_exclusion

# Non-raising audit returning a structured report
report = audit_farir_exclusion(Path("manifests/in_scope_figure_register.json"), raise_on_violation=False)
print("Passed:", report["passed"], "| Violations:", report["violation_count"])

# Strict mode (default raise_on_violation=True) raises FarIRExclusionError on leak
try:
    audit_farir_exclusion({"collection": "FTMW methodology manuscript", "figure": "Fig1"})
except FarIRExclusionError as exc:
    print("Blocked out-of-scope content:", exc)
```

## 5. `CoChem-BASE` Provider Dispatch & `CoChem-SPYFY` Legacy Archiving

### `CoChem-BASE` Provider (`scribe_provider`)

`CoChem-SCRIBE` registers `scribe = "cochem_scribe.provider:scribe_provider"` under `[project.entry-points."cochem.modules"]` with four canonical operations:

- `render_geom_comparison`
- `render_kinetic_rxn_profile`
- `verify_source_register`
- `audit_farir_exclusion`

```bash
cochem-scribe provider-info
```

```python
from cochem_scribe.provider import dispatch_operation, execute_handoff, scribe_provider

meta = scribe_provider()
print(meta["module_id"], meta["version"], meta["operations"])

register_report = dispatch_operation("verify_source_register", {"verify_on_disk": False})
print("Register passed:", register_report["passed"])

# Or execute a CoChem-BASE cochem.module-handoff/1 JSON envelope directly:
receipt = execute_handoff(
    handoff_path="handoff_render_geom.json",
    output_directory="out/handoff_receipts",
)
```

### Archiving `CoChem-SPYFY` Pickett Verification Files

For classical spectroscopists cross-validating `CoChem-SPYFY` Bayesian fits against JPL SPFIT/SPCAT, `scribe_legacy_bundler.LegacyVerificationBundler` packages `.lin`, `.cat`, and `.fit` files alongside Zstandard-compressed archives and a `checksums.sha256` manifest inside `Legacy_Verification.zip`:

```python
from pathlib import Path
from scribe_legacy_bundler import LegacyVerificationBundler

bundler = LegacyVerificationBundler()
bundler.legacy_files = [Path("output.lin"), Path("output.cat"), Path("output.fit")]
bundler.create_legacy_bundle()
```
