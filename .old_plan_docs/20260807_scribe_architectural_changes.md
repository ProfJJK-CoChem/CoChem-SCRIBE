# CoChem-SCRIBE Architectural Changes (2026-08-07)

This document outlines the requisite architectural refactoring for the `CoChem-SCRIBE` module. It transitions SCRIBE from a simple zip utility and basic LLM prompter into a continuous background daemon capable of memory-aware tensor archiving and full academic publication scaffolding. These changes are mandatory before generating the executable SCRIBE workflow.

## 1. Zstandard Background Archiving Daemon
**Target File:** `scribe_doc_manager.py`

**Current State:** 
SCRIBE relies on a static user-triggered button to compress 7 hardcoded text files into a standard `.zip` archive at the very end of the computational pipeline.

**Required Architectural Change:**
- **Asynchronous Daemon:** SCRIBE must be rebuilt as an `asyncio` background daemon that is spawned by `CoChem-BASE` at the beginning of the workflow.
- **Memory-Aware HDF5 Chunking:** Massive 3D tensors generated by TORQ and SpycFit (e.g., $J=80$ partition functions and DVR grids) cannot be zipped in memory without crashing Jupyter. SCRIBE must attach to `cochem_state.h5` as a read-only spectator. It will monitor memory thresholds and flush the data to disk using highly compressed **Zstandard (`.tar.zst`)** in 500MB chunks during idle CPU cycles.
- **Pre-Flight Module Sync:** SCRIBE must verify that all modules share the exact same schema version string before allowing final archive serialization.

## 2. Dynamic Parsing & LaTeX / BibTeX Autogeneration
**Target File:** `scribe_payload_builder.py`

**Current State:** 
The payload builder reads the static `cochem_system_config.json` to tell an LLM what modules were active to write a generic "User Guide".

**Required Architectural Change:**
- **Log Parsing:** SCRIBE must actively parse the raw ORCA `.out` and MACE `.log` execution streams to capture any adaptive fallbacks (e.g., `MACE` falling back to `AIMNet2` due to transition metals) that occurred *during* runtime.
- **APS-Compliant LaTeX Methodology:** SCRIBE must auto-generate a rigid `Methodology.tex` file detailing the precise DFT functionals, Basis Sets, MLFF Tiers, Grid Densities (`DefGrid4`), and hardware utilized.
- **Dynamic CrossRef API:** SCRIBE must scan the utilized theories and dynamically query the CrossRef API to pull the exact DOI citations (e.g., Grimme's D4, Colbert-Miller Sinc-DVR) and compile a complete `manuscript.bib` file.
- **Conditional Jinja2 Templating:** SCRIBE's LaTeX builder must utilize Jinja2 templating. If the user executes a partial pipeline (e.g., running BASE -> TOPOS -> SpycFit but skipping TORQ), SCRIBE must gracefully omit the TORQ methodology section without leaving broken references or blank tables.
- **LAM Protocol Reporting:** If TORQ's `LAM_TRIGGER_REQUIRED` flag was activated, SCRIBE must automatically inject a standardized paragraph into the LaTeX file explicitly justifying the use of Sinc-DVR over the rigid-rotor harmonic oscillator approximation for that specific structure.

## 3. Publication Visualization Pipelines
**Target File:** `scribe_figure_generator.py` (New Subsystem)

**Current State:** 
SCRIBE produces no scientific figures, molecular renderings, or spectral plots.

**Required Architectural Change:**
SCRIBE must be equipped with Plotly, Py3Dmol, and TikZ generation logic to unpack the HDF5 tensor and generate publication-ready artifacts for each module:
- **TOPOS Artifacts:** 
  - Interactive HTML 3D Carousels of the top isomer geometries.
  - Exporting Non-Covalent Interaction (NCI) domains into `.cube` format.
  - LaTeX tables summarizing enantiomeric excess/racemic distributions from the Crusher chiral buckets.
  - Boltzmann population stacked bar charts derived from final DLPNO-CCSD(T) energies.
- **TORQ Artifacts:** 
  - 2D contour maps of Colbert-Miller Sinc-DVR probability wavefunctions overlaying the classical PES grids.
  - Plotly graphs directly overlaying harmonic (VPT2) vs anharmonic (DVR) infrared spectra.
  - LaTeX TikZ diagrams illustrating A/E tunneling splittings.
- **SpycFit Artifacts:** 
  - Plotly scatter graphs demonstrating the drift from the rigid Bayesian priors to the fitted posteriors.
  - Box-and-Whisker plots displaying the leverage and variance of the Leave-One-Isotopologue-Out (LOIO) cross-validation routine.
  - High-resolution `.svg` vectors of the final JAX `vmap` Voigt spectral convolutions (both Microwave and UV-Vis Absorption).
- **Mass Spectrometry Artifacts:**
  - Parsing `.res` QCxMS files to generate theoretical MS fragmentation mass-to-charge ($m/z$) bar charts overlaying experimental GC-MS data.

## 4. Scaffolded LLM "Results & Discussion" Generation
**Target File:** `scribe_inference.py`

**Current State:** 
The engine queries the Gemini API with a rigid prompt to write a "User Guide", with a basic offline fallback.

**Required Architectural Change:**
- **Results Compilation:** The LLM payload must be expanded to encompass the generation of the manuscript's "Results & Discussion" section. SCRIBE will feed the LLM the final Bayesian SpycFit parameters, the identified global minimum, and the kinetic barriers.
- **Offline Fallback Transparency:** If SCRIBE fails to reach the Gemini API (e.g., executing on an air-gapped HPC node), the generated offline document must prominently display a bold watermark stating that the AI interpretation phase was bypassed.

## 5. Legacy Verification Bundling
**Target File:** `scribe_doc_manager.py`

**Current State:** 
Zip file bundles random `.log` files and JSONs.

**Required Architectural Change:**
- SCRIBE must systematically isolate the Pickett `.lin`, `.cat`, and `.fit` files generated by `SpycFit` into a specific `Legacy_Verification.zip` bundle, ensuring classical spectroscopists can quickly cross-validate the ML-driven assignments using legacy tools like SPFIT/SPCAT.
